# Blocking execute_route

## Objective

Change `execute_route` so the tool call waits for the route to reach a terminal state instead of returning immediately after acceptance.

## Requirements

- Preserve the existing asynchronous navigation engine and FIFO queue.
- `execute_route` must return only when the route is completed, blocked, failed, cancelled or interrupted.
- Return the final state, completed waypoint count, and individual waypoint outcomes.
- Keep `move_to(queue=true)` asynchronous.
- Avoid polling through repeated LLM tool calls.
- Handle cancellation, timeouts and simulation shutdown without leaving unresolved promises.
- Preserve existing navigation constraints and recording functionality.

## Scope and architectural constraints

- Modify **only the Pi explorer adapter/tool layer** (`experiments/pi-explorer/`) and its associated tests.
- Do not modify `src/` or the core navigation API.
- Keep `world.interact.executeRoute()` asynchronous and unchanged.
- Implement waiting inside the Pi `execute_route` tool, using the existing `navigation_status` API internally.
- The tool must wait asynchronously without blocking the browser simulation or Node.js event loop.
- Do not introduce events or new navigation mechanisms into the core.
- Preserve the existing behavior of all other tools.

## Acceptance criteria

- Successful routes return `completed`, not merely `accepted`.
- Blocked routes return the failure and partial execution results.
- No model intervention is required between waypoints.
- Existing tests remain passing.
- Add regression tests for success, blocking, cancellation and shutdown.

Choose the implementation details. Do not introduce unnecessary dependencies.
