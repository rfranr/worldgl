# Execute Route

**Dependency:** Assignment 1 must be completed and accepted.

## Objective

Introduce an `execute_route` tool that lets an agent submit an ordered sequence of waypoints in one call.

Reuse the navigation queue developed in @TASK12_01.md

## Requirements

- Accept an ordered sequence of waypoints.
- Validate the route before accepting it, without bypassing movement constraints.
- Submit the accepted waypoints to the existing navigation queue.
- Return an immediate acknowledgement with an identifier for tracking execution.
- Execute waypoints sequentially.
- Support progress inspection through `navigation_status`.
- Support cancellation through the existing abort mechanism.
- Stop on blocked or failed movements and preserve the partial execution result.
- Distinguish route acceptance from route completion.

## Acceptance criteria

1. An agent can submit a multi-waypoint route in one call.
2. The route executes without requiring a model turn between waypoints.
3. Existing `move_to` functionality remains available.
4. Route progress and terminal outcomes are observable.
5. Abort, failure, and partial completion are handled consistently with Assignment 1.
6. Automated tests verify successful routes, partial execution, cancellation, and invalid routes.
7. Existing quality checks pass.

## Constraints

- No second navigation engine.
- No duplicated movement or queue logic.
- No additional dependencies without approval.
- Preserve existing experiment inspection and recording functionality.

The agent may choose the implementation and API details, provided they remain compatible with the navigation semantics established in Assignment 1.
